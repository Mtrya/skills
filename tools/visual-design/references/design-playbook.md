# PPT 设计手册

按场景选打法。所有场景共享一套通用纪律，再叠加各自的专项要求。

## 通用纪律

1. **标题串读测试**：把所有页标题单独提出来按顺序读，应能串成完整的论证线。标题承载结论，不是栏目名。
2. **每页一个中心思想**：一页讲透一件事；支撑它的证据、图表、注释围绕它组织。
3. **密度分场景**：阅读型报告高密度，演讲型低密度。判断不了就按阅读型做。
4. **视觉一致性**：配色、字体层级、页眉页脚、标题格式全程统一；元素跨页坐标稳定，翻页不跳。
5. **拒绝默认**：默认配色、默认网格线、默认阴影一律处理掉。细节决定成败。

## 场景一：分析决策类（研究报告、咨询汇报、数据分析）

默认按**阅读型**做，对标顶级研报/咨询公司标准。

**内容组织**
- 每页有深度：核心结论一眼可得，读完全页值得花 5 分钟。
- 支撑呈瀑布：标题下判断 → 若干独立支撑判断 → 每条挂一句可验证的证据。
- 正文页标题优先用陈述句（"欧洲电动重卡电池 2030 年达 48GWh——六年 16 倍"），不强求。
- 数据是论证主体：每张图带完整坐标轴、单位、图例、来源、统计口径，脱离正文也成立；来源必须真实，严禁编造。
- 图表上直接标拐点、关键值，并配文字说明：它证明了什么、能看出什么、对决策的含义、来源和边界。
- 有结构关系（顺序、对比、循环、因果）的内容用结构图/SmartArt 呈现，不用文字平铺。

**版式纪律**
- 除非明确要求，**禁用圆角矩形/卡片堆层级**——用线段、留白、字号差异做层次。
- 单个基础图表不得占半版以上宽度；鼓励一页多图/多内容组合。
- **禁均分构图**：不默认三等分、四等分、2×2 矩阵、"三栏+标题+结论"三段式，除非论证过确实无他选。

**视觉参考（白底单主色骨架）**
- 纯白底，全篇仅一个主色（藏青、墨绿等金融咨询常用色）承担骨架：标题强调、表头、导航高亮、主图表系列、序号标记；配同色系 2–3 级浅阶和中性灰。
- 标题即结论；格式固定（kicker→主标题→副标题，或标题+结论副题）；粗衬线标题+无衬线正文，分工明确，层级严格一致。
- 页眉页脚坐标全篇固定：导航常显（当前节高亮，靠位置而非换色区分），页脚固定"来源："+页码。
- 密度节奏：正文页高密度，图表为主体、文字服务于证据；封面、章节页、结尾页用留白透气。
- 位置纪律：结论在页首标题 → 证据图表居中 → 解读在图侧或侧栏 → 来源口径在页脚 → 行动建议只在末页。各归其位，全篇一致。
- **图表去默认化**：系列色重配为主色阶梯+灰；删竖网格线（至多留极浅横线）；数据标签只标关键点和端点；实际值实线 vs 预测值虚线/斜纹；图表正下方放来源+口径说明。
- 关键值直接标在图上：大数字标注总量，拐点/差距/增速用箭头+引导线+一句话注释，评级用 Harvey balls 或徽标。
- **表格规范**：深色表头白字、极细横分隔线（无竖线无粗框）、数字右对齐文字左对齐、首列主题词加粗；大表配解读面板。
- 线条与对齐：全部元素对齐统一左缘和隐形栏线；分隔只用极细线，强调只用主色短粗条或粗竖条；面板直角无阴影；圆角只许出现在小标签上。
- 表面干净：无阴影、无渐变、无纹理、无发光、无默认色——质感全靠留白、对齐、单色阶梯和线条纪律。

## 场景二：商业计划类（BP、融资路演、项目提案）

- 叙事主线：痛点→方案→产品→市场→模式→壁垒→团队→财务→融资需求，顺序可调但不断链。
- 每页回答投资人一个问题；市场规模页必须给出测算逻辑（自上而下/自下而上），不是只甩一个数字。
- 财务页：3 年预测起步，关键假设列在表旁；融资页说清金额、用途拆分、里程碑。
- 视觉上允许比分析类更强的品牌感：封面可大图，但正文页仍守对齐和层级纪律。

## 场景三：技术工程类（技术方案、架构评审、项目汇报）

- 架构图用形状+连线精确绘制：分层清晰、数据流向有箭头、图例齐全；不拿文字描述代替图。
- 代码片段用等宽字体、浅底、限量（单页不超过 ~15 行），只展示关键片段。
- 对比方案用表格：维度行×方案列，结论行高亮；每个维度一句可验证的话。
- 进度/排期用甘特式横条图或时间轴形状组合，里程碑用菱形标记。
- 性能数据给基准测试条件（硬件、版本、数据规模），不给无条件的数字。

## 场景四：通用/其他

- 培训课件：一页一个知识点，步骤类内容编号化，配练习页。
- 产品介绍：功能→场景→证据三段式，截图优先于描述。
- 工作总结：数据先行，成果量化，问题与计划各一页收尾。

## 设计系统机制

当用户提供设计系统（design system）时：
1. 通读全部规范（色板、字体、组件、版式样例）。
2. 把规范映射为 pptd theme（colors/textStyles）沉淀到主入口，所有页面引用 token，不硬编码色值。
3. 严禁混入设计系统之外的样式——哪怕某个元素"这样会更好看"。
