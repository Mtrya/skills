# 大纲设计参考

## 先做四个分析（可并行或由一个 agent 顺序完成）

1. **需求分析**：从用户请求和上传材料中提取全部显性与隐性要求（题目、受众、篇幅、格式、时间窗、必须覆盖的点）。
2. **研究产物分析**：通读已有材料和研究工作目录下的相关证据文件，提炼主题、数据点和来源结构。
3. **结构设计**：按受众和目的安排章节层级、权重分配与篇幅。
4. **内容规划**：为每章定义具体内容点、必备元素（表格/案例）、呈现方式。

若用户上传了文件，先做文件清点与要点提取，再合并进大纲。

## 四级标题示例（按报告需要选择层级与编号）

```
# 标题（H1，不编号；仅主标题与"参考资料"节）

## 1. 章标题（H2，编号）
### 1.1 节标题（H3，编号）
#### 1.1.1 内容点（H4，编号——最小执行单元）
```

- 内容点是写手的任务清单：**具体、可执行**，含实体/数字/方向；尚未证实的要点写成待回答的问题。内容点不必全部成为标题。
- 按阅读需要选择标题深度；逻辑更深时也可拍平为同级条目或并入上级描述。
- 摘要/执行摘要仅正式研究报告需要，放在 `## 1.` 之前且不编号。
- 每章标注需吸收的关键来源，按需安排目标字数与表格/案例/图表。这让大纲从"目录"变成"执行规格书"。

## 大纲阶段就要带引用

大纲中出现的具体事实与数据点，就地标注来源链接；用户文档、仓库文件和数据也可以作为来源，详见 citation.md。外部来源优先级：T1（政府、国际组织、顶刊、法定披露）> T2（主流通讯社、权威智库、企业官方）> 拒用（内容农场、匿名论坛、未核验社媒）。

## 保存前自检

- [ ] 用户的每条要求都有对应章节
- [ ] 层级适合内容与阅读需要
- [ ] 使用编号时保持顺序一致
- [ ] 内容点具体可执行，无"讨论/分析 XX"式空条目
- [ ] 每章明确关键来源，篇幅与图表安排符合需要
- [ ] 文末"参考资料"节列出中间产物文件（大纲、原始引用集、用户上传文件）
- [ ] 无多余内容：不要大纲总结表、结构图、emoji

## 示例骨架（仅示意格式，结构须从具体题目生长出来）

```markdown
# 2025 年全球 AI 芯片市场分析

## 执行摘要
### 关键发现
#### 市场规模预计 2028 年达 XX 亿美元，数据中心需求为主引擎（来源：…）
#### 某厂商保持 70%+ 份额，但面临定制芯片竞争（来源：…）

## 1. 市场概览（约 3000 字，2 张表）
### 1.1 市场规模与增速
#### 1.1.1 2024 年全球市场 XX 亿美元，2020 年以来 CAGR XX%（来源：…）
#### 1.1.2 按应用拆分：数据中心 60% / 边缘 25% / 车载 15%（来源：…）
### 1.2 需求驱动
#### 1.2.1 大模型训练算力需求每 6 个月翻倍
#### 1.2.2 主权 AI 项目创造新需求（表：十大国家项目）

# 参考资料
## {报告名}_outline_references_raw.md
- 类型：引用收集；路径：…
```

需要独立大纲文件时，可保存为 `{报告名}.agent.outline.md`。
