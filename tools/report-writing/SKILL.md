# 报告写作（Report Writing）

把一份分析报告当作一条有质量闸门的流水线来跑：**研究备料 → 大纲设计 → 分章写作 → 四重审校 → 装配交付**。篇幅与呈现方式随受众和目的调整。按用户要求的格式交付，未指定时默认 Markdown；docx/pdf 使用适用的文档工具，中间格式按需选择。

## 入口决策

```
用户请求
  ├─ 已有材料足以支撑报告 → 直接进入阶段 1
  ├─ 存在影响主张或结论的证据缺口 → 定向补充研究（见下），再进阶段 1
  ├─ 用户给了大纲只要正文 → 阶段 2 起
  ├─ 只要大纲 → 阶段 1 后交付即止
  └─ 给了草稿要修改 → 阶段 3 起
```

**补充研究**：先读已有材料，仅围绕影响主张或结论的证据缺口检索，深度由问题决定，不设检索轮数配额；做交叉验证（标出置信与冲突点），再提炼跨材料洞察。需要落盘时，优先沿用仓库已确立的研究材料目录；没有既定目录则用 `mktemp -d /tmp/research-XXXXXX` 创建本次任务的 `/tmp/research-xxx` 目录，不在仓库中新建 `research/`。其中可按需保存 `{主题}_dim{NN}.md`、`{主题}_cross_verification.md`、`{主题}_insight.md`。若配合同样的 deep-research 类技能使用，直接复用其产物。

## 阶段 1：大纲设计（先读 references/outline.md）

大纲是写手的**执行合同**，不是目录。要点：

- 标题层级与编号按内容需要选择；references/outline.md 的四级标题仅为一种示例。
- **内容点必须具体、可执行**（含实体、数字、方向），如"2024 年全球动力电池成本同比下降 14%，主因是中国 LFP 渗透率提升"；禁止"讨论 XX 趋势"式空泛条目。尚未证实的内容写成待回答的问题。
- 每章标注需引用的关键来源；目标字数、表格/案例/图表按需安排。
- 需要保存大纲时可用 `{报告名}.outline.md`。用户要求完整报告时继续写正文，只在缺失信息实质影响方向时提问；遵守用户明确要求的审阅节点，只要大纲则直接交付。

## 阶段 2：分章写作（先读 references/content.md）

- **按需拆分章节任务。** 多章时先做依赖分析，分轮次派发：无上游依赖的章先写；摘要、结论、综合章必须在被它们总结的内容完成之后写。
- **简报制度**：写每章前，把适用的内容解析成具体值再动笔（详见 content.md 的检查清单）：文风（可参考行业研究/咨询/政策简报/技术）、配色方案（需要图表时统一，可参考 8 套示例）、引用规范、该章大纲节选、前置章节要点、该章可用的证据文件。
- 核心写作纪律：**每段至少承载一个具体信息点**（删了它论证会受损吗？不会就是注水）；按信息关系选择散文、列表、表格或图形，解读说明趋势、异常和含义，不设字数下限；来源链接紧跟相关主张，用户指定引用规范时从其要求。
- 需要分章文件时可分别存为 `{报告名}_sec{NN}.md`，章节正文使用来源链接，集中参考资料列表按需生成。

## 阶段 3：四重审校（先读 references/review.md）

顺序执行，每关只有过/不过，不过就带"整改简报"（文件+位置+问题+修法）原地重写，每章每关最多两轮：

```
章节编辑（逐章：完整性/密度/深度/引用/文笔/图表合规）
  → 衔接编辑（通读全稿：过渡/术语一致/逻辑递进/数据一致/去重）
    → 首尾审校（摘要准确自包含；结论综合而非复述；建议可执行；局限诚实）
      → 引用管理（核对来源链接，按需去重汇总；用户指定格式时从其要求）
```

## 阶段 4：装配

引用管理完成后，按顺序装配各章，按需附参考资料；校验交叉引用、标题层级、来源链接，在用户要求的格式与位置交付。Markdown 文件可用 `{报告名}.final.md`，其他格式不强制保留 Markdown 中间产物。

## 核心原则

1. **证据先行**——基于已有材料写作，遇到影响论证的缺口再定向补充研究。
2. **交付格式优先**——遵循用户要求，未指定时默认 Markdown。
3. **中间文件按需**——研究资料使用上述工作目录，最终报告遵循用户要求与项目约定。
4. **重写原地进行**，不留版本垃圾。
5. **语言一致**——正文、提示词、交付物全部使用用户的语言。
6. **用户提供的原始材料要传到写手手里**——研究摘要会丢失精确数字和细微论证，把相关的原始文件路径按章择要传给写手，而不是只给摘要。
