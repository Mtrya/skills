# 学术汇报 Slides

把讲稿的推理变成台上能指着讲、台下能马上读懂的画面。每页给听众一个进入点，并让他们看出这一页与前后内容的关系。用准确的技术语言，讲清机制再下判断。

## 从采访到初稿

1. **先弄清用户现在要做什么。** 采访、读论文、讨论主线、制作和评审是不同工作。如果用户要求分阶段，就按这个顺序推进。讨论时给出可以直接评议的开场原话、主线或示意页。收到制作指令且材料已足够，就做一版完整可看的稿子。
2. **采访先问用户知道的事。** 确认时长、语言、听众基础、课程或会议要求、演示者习惯的文字密度，以及已有模板。遇到「不要有 AI 味」之类的偏好，问一个具体反例。一个答案会决定下一问时，一次只问一项。
3. **研读材料时沿因果关系推进。** 从任务和可用信息出发，理清现有做法为何形成、困难在哪里、这项工作改变了什么、这些改变怎样起效。核对图、式、表、单位与实验条件。选一两个真实对照讲深，把工作的结果和自己的解释写清楚。用户想逐点学时，每次只解一个依赖点。终端不能渲染公式时用纯文本说明，正式稿再做数学排版。
4. **先谈全局，再进入细节。** 给用户看整场的核心问题、各部分要回答的子问题、主要证据，以及证据能支持的结论。开场从工作背景进入，或从现象、假设、实验反差进入，取决于用户的偏好与听众起点。每一部分结束时交代下一问题从哪里来。主线、取舍与证据定到能出初稿时，把页序、逐字稿和局部样式留到看着成品一起改。
5. **用合适的模板做可编辑的初稿。** 有用户指定的模板就使用它，优先保留已定的页面尺寸、品牌和交付格式。需要找机构模板时，核实来源，分清机构官方标识与社区主题。给每页留能提醒讲者、帮助观众跟上的文字，推导细节和口头过渡可进讲者备注。给限时汇报标注估计用时，并让总时长符合约束。

按论证选组织方式。实证研究可以从待验证的主张出发，经由比较设计走到结果与适用范围。系统报告可以先用一个请求走完整条路径，再放大有新意的模块，最终回到性能或失败条件。两者都可以先给全景再展开细节，并在需要听众形成具体预期的地方用一个贯穿案例。

## 信息架构与视觉表达

- **一页有一个主角。** 先决定这一页要看图、读数，还是想清一个问题。用字号、位置、留白和克制的强调色让它最先被看到。标题说清本页的对象或观察结果，例如「效应随剂量增加而趋于饱和」。页面上的文字负责解释图中需要推理的关系。
- **让呈现方式对应信息结构。** 流程和依赖用图，时间关系用时间轴，趋势和分布用图表，需逐项核对的精确值用表格。小矩阵也可以用于讲清逐行、逐列约束。把同一张图拆到相邻页时，复用位置、尺寸和语义色，让本页新增或正在解释的部分突出。
- **让箭头和符号有明确含义。** 区分事件的时间先后、数据的传递、决策的依赖和反馈的方向。例如，机器学习方法图应把数据采集的时间顺序和训练监督的方向说明白。图、公式与讲稿使用同一套变量、上下标和正斜体约定。读者应能沿图复述机制。
- **用真实材料帮助理解抽象概念。** 从论文、项目页或用户提供的素材中选择能解释当前问题的材料，可以是原始观测、样本、现场照片、轨迹或界面示例。图注说明材料来自何处、展示什么，并区分示意与实测。
- **在该停的地方改变节奏。** 当几页连续使用结构图或数据表，把视线拉回核心问题、现场照片或一项最有信息量的结果。可以在原有过渡页放大问题，也可以用精确数字配比例条。决定是否加页时看它有没有现场用途，并核对时长。
- **让实验结论有可追溯的比较。** 标注指标、单位、样本量或分母、基线和好坏方向。用颜色或字重突出最值得读的对照，画比例条时统一零点与尺度，保留原值。核对分组、干预时机或不确定性是否会改变结论。例如，训练后干预回答现有模型如何依赖一个信号，改变条件后重新训练回答模型能否学会补偿。实验描述缺了影响结论的信息时，指出缺了什么。
- **干净地结束。** 回到开头的问题，说明机制、收益和适用边界。根据场合决定是否需要参考文献、致谢或备查。备查页对应具体的问答需求，有明确删除决定时按该决定交付。

## 版式、字体与读图

- **先定版心，再定几个层级。** 统一内容页的边距、标题基线、正文起点和出处位置，封面与收束页可以有独立结构。用主文字、辅字、结构细线、浅填充和画布建立明度层级。沿用模板合适的色彩，在不同方法分支、主方法与对照等需要区分的地方固定颜色的含义。
- **检查可见的边界。** 同一条横向流程的单行和双行节点可等高。让连线走在节点之间，留下转弯与箭头的空间。浅底模块或浅边照片在最终画布上看不清时，加细描边。照片与文字并排时，比较照片上缘、首行字面和表格起点的视觉位置。强调块需要外移时，让块内文字和页面版心对齐。
- **按投影阅读来选字体。** 中文正文用清楚的常规字重，强调或小节点标题可先试 Medium。英文、中文和数学看实际字面高度与笔画，尤其是小写变量、标点、上下标、数字和单位。对数学无衬线或衬线的取舍有争议时，用同一组方法页和数据页做并排渲染，按可读性与气质选择。数字按列右对齐或小数点对齐，保留数据原有精度。
- **把轻量样式用在有收益的地方。** 细横线可以固定阅读起点，短竖线可以托住一句关键问题，微灰底可以让白色模块有边界。用渲染后的页面决定这些处理是否有用，避免把同一套卡片、颜色或装饰铺遍全稿。

## 审校、修订与交付

1. **先看当前成品。** 用户给出评语或参考课件时，打开对应 PDF 或可编辑稿，区分可复现的错误、审美判断和可选方案。需要借鉴时找实际参考页并看它解决了什么问题。根据用户的目标与成品中的证据决定采纳哪些建议、怎样落地。
2. **按影响修。** 先处理贯穿多页的逻辑、版心与图表规则，再修单页拥挤、裁切、换行和对齐。保留已有共识与有效的结构。用户只要求评审时，给出页码、证据和精确改法。用户要改稿时，同步更新可编辑源文件和导出件。
3. **按交付尺寸重新看一遍。** 从头翻导出的文件，检查整体节奏、封面安全留白、实际读图顺序，以及图注、公式和页脚。重点放大核对长表格、数字对齐、单字换行、中英数间距、节点与连线、文献悬挂缩进和机构标识。编译成功与否只回答文件能不能生成，光学对齐和投影可读性从渲染图判断。
4. **交付可继续工作的材料。** 按任务提供可编辑源码、所需资源和可直接投影的成品，确保两者来自同一次构建。标明需要用户核对的假设或确实存在的限制。用户要做进一步选择时，把完整文案、修改前后页或可运行的文件交给他们判断。

制作或精修 Beamer 时，读 [Beamer 实操](references/beamer.md) 了解导言区字体与颜色、主题接入、页脚出处、图表与数据表的示例代码，以及编译后核对。
