# README 与项目介绍

让读者看见这项工作对自己的价值，并愿意进一步了解或亲手使用。

## 组装开头

默认按“核心收益—代表性证据—下一步入口”组织开头：

1. **写出收益。** 用一句话说明这是什么、让目标读者能做到什么，突出相对已有选择的关键变化。将技术特性译成读者关心的效果；必要的门槛或条件随收益说明。
2. **让收益可见。** 按下表选材料，在安装说明前展示。图注直接点出该看哪里、得出什么结论；演示同时呈现输入或条件与结果。
3. **接上行动。** 在证据附近提供主要入口，以“在线体验”“运行示例”“查看评测”等动作命名。其余链接按用途归组。

| 核心吸引力 | 优先展示的材料 |
| --- | --- |
| 效果或能力出色 | 有代表性的输入与输出、同任务效果对比；动态能力用短视频或动图。 |
| 更快、更省或门槛更低 | 同任务下的耗时、资源或成本对比，并说明它让读者多做了什么。 |
| 方法有巧思 | 一个具体难题与关键解法的对照，突出改变结果的那一步。 |
| 数据集或 benchmark 带来新价值 | 代表性样本或任务，连同它揭示的差异、支持的研究问题或使用产出。 |

标题、图像、徽章和链接按作用取舍与排序；让核心收益与证据保持相邻。

## 把兴趣接到第一次使用

选择一个能体现卖点的最小任务作为 Quick Start，给齐前置条件、示例输入、必要命令、预期结果及查看位置。多个版本或配置并存时，为主要读者推荐起点，并说明何时改选其他项。

完整运行昂贵时，区分环境检查与成果体验：smoke test 说明验证了什么，另给小规模真实示例、在线 demo 或预计算结果供读者感受能力。

其余正文按读者接下来的问题组织：为什么有效、效果如何、怎样接入、怎样复现或扩展。不同意图需要不同路径时，用“我想做什么 → 去哪里”的短表分流。完整参数、安装分支与长篇推导放入专门文档；影响选择的适用条件留在相应入口旁。

## 可借用的手法

- [Strata](https://github.com/Niko1221/Strata#readme)：开头把引擎能力表达为“在自己的游戏电脑上运行大模型”，配上实际生成案例；后文按硬件、内存提供安装与模型选择，速度表将生成和预填充称为回答出现、读入提示的速度。借用到技术系统介绍时：先写用户获得的能力，再把指标、配置和技术术语转成体验与选择。
- [SAM 2](https://github.com/facebookresearch/sam2#getting-started)：按图像预测、视频预测提供短代码，分别链接完整 notebook；模型表并列规模、速度与质量。能力或版本不止一种时，用任务示例展示怎么用，用取舍表帮助选择。
- [SWE-bench-Science](https://github.com/OpenMOSS/SWE-bench-Science#start-here)：用 Start Here 表连接看结果、浏览数据、运行评测等意图；Quick Start 将无需模型调用的基础设施检查与真实 agent 运行分开。多种资源共同发布时，借用其任务分流与分步上手方式。

## 交付前检查

在实际页面检查开头与常见屏幕宽度，确认关键差异可辨、图注可读、入口可达。核对 Quick Start 的输入、命令与结果是否衔接，是否要求读者自行寻找未链接的文件或猜测配置。
